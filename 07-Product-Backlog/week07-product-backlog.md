## Product Backlog

### Story 1

**User Story:** As a front desk coordinator, I want to view appointment availability and prevent scheduling conflicts, so that I can schedule patients accurately and reduce double bookings.

**Acceptance Criteria:**
1. The system displays available appointment times.
2. The system prevents two patients from being booked for the same appointment time with the same provider.
3. Staff receive a message when a selected appointment time is unavailable.
4. Staff can save a confirmed appointment.

**Story Points:** 13

**MoSCoW Priority:** Must Have

### Story 2

**User Story:** As an intake coordinator, I want to use a standardized patient intake form across all six clinics, so that patient information is collected consistently and accurately.

**Acceptance Criteria:**
1. The same required intake fields are available at all six clinics.
2. The system identifies missing required information before submission.
3. Staff can save a completed intake form.
4. The system displays a message when required information is missing.

**Story Points:** 8

**MoSCoW Priority:** Must Have

### Story 3

**User Story:** As an IT support specialist, I want patient information access to be based on staff roles, so that sensitive information is protected from unauthorized access.

**Acceptance Criteria:**
1. Staff must sign in before accessing patient information.
2. Staff can access only the information and features permitted for their assigned roles.
3. The system denies access to unauthorized users.
4. The system displays a message when a user does not have permission to access information.

**Story Points:** 5

**MoSCoW Priority:** Should Have

### Story 4

**User Story:** As a clinic manager, I want to view and track unresolved scheduling issues, so that I can help staff resolve problems and keep clinic operations organized.

**Acceptance Criteria:**
1. The system displays a list of unresolved scheduling issues.
2. Each issue includes a description, status, and date reported.
3. The clinic manager can update an issue's status.
4. The system displays whether an issue is open or resolved.

**Story Points:** 5

**MoSCoW Priority:** Should Have

### Story 5

**User Story:** As a front desk coordinator, I want to customize dashboard colors, so that I can personalize the appearance of my workspace.

**Acceptance Criteria:**
1. The user can choose from available dashboard color options.
2. The selected color is displayed on the dashboard.
3. The dashboard returns to its default colors when the user selects the default option.

**Story Points:** 2

**MoSCoW Priority:** Won't Have This Time

---

## Prioritization Rationale

### Must Have Justification

Scheduling is a Must Have because RCHN needs to reduce double bookings and scheduling confusion across its six clinics. Staff need to see available appointment times and avoid scheduling conflicts. Without this feature, the system would not solve one of the main problems identified by users. Standardized intake forms are also a Must Have because they help staff collect patient information consistently across all locations.

### Won't Have Rationale

Customizing dashboard colors is excluded from the current planning period because it does not directly solve RCHN's main problems with scheduling and patient intake. Although customization could improve the user experience, the team should focus on essential features first. This item can be reconsidered in a future phase if there is enough time and resources.

---

## Backlog Reflection

### Persona Connection

Story 1 connects to the front desk coordinator persona from Week 3. Front desk staff need an organized and reliable way to schedule appointments because double bookings and confusing workflows can create extra work. Showing appointment availability and preventing scheduling conflicts would help staff work more efficiently and provide a better experience for patients.

### Scope Connection

Story 2 connects to the Week 5 scope definition because the project focuses on improving patient intake and scheduling across all six RCHN clinics. Standardized forms, required fields, and validation support consistent information collection. This feature stays within the project's scope by improving the existing intake process instead of adding unrelated features.
